# 手机适配反馈

0.5.9 使用同一个 APK 检测实际 NFC 能力。接口存在、权限允许、命令被接受、发现标签、D1 正确、实屏刷新是不同阶段；反馈应注明停在哪一步。

## 弹窗含义

| 提示或状态 | 已确认的事实 | 可尝试的操作 |
|---|---|---|
| 系统缺少专用 NFC 接口 / `missing_interfaces` | 当前运行时接口缺失或签名不匹配，弹窗列出接口类别 | 标准 NFC；导出反馈检查 ROM 差异 |
| 检测到接口，暂未确认适配 / `unadapted_controller` | 发现接口与芯片标识，现有后端未覆盖该控制器 | 标准 NFC；根据芯片协议研究后端 |
| 同上 / `unidentified_controller` | 尚未可靠识别控制器协议能力，不能据此选择私有命令 | 导出接口清单与芯片来源，补充识别方式 |
| 专用唤醒暂不可用 / `command_rejected` | ST 读帧被拒，后台已确认未改变配置后回退 | 查看原始命令、响应和恢复记录 |
| `not_checked` | 未通过 shell 探测专用接口，或用户选择了标准通道 | 需要专用检测时连接 Shizuku；不代表接口缺失 |
| `experiment_disabled` | ST54L 实验模式未开启 | 按实验说明决定是否启用；不弹“系统缺少接口” |
| `service_stale` | 连接了较旧的诊断后台 | 重启 Shizuku，返回 App 重新连接 |
| `probe_failed` | 权限、服务或探测调用失败 | 排除连接/授权问题；不能直接归为不支持 |

未知芯片不会自动收到 NXP 或 ST 配置命令。缺少接口、未适配或未识别时可以尝试标准 NFC，但目标屏可能仍需要系统未开放的 7A 唤醒能力。

## 如何反馈

1. 更新后连接 Shizuku，在设备页点「检查手机兼容性」。此操作读取接口和配置，不启动寻卡或写入图片。
2. 需要复现时，先点「检测屏幕」；推图问题再使用同一张照片复现。保持 App 前台，等待结果后导出本次会话。
3. 在提示框点「导出适配反馈」，或日志页分享/保存 ZIP。诊断文件写入本机，导出后由用户选择分享目标，不自动上传。
4. 同时描述屏幕型号/固件（若知道）、按了哪个按钮、操作步骤、预期与实际现象、是否使用外部供电。系统与 App 版本会自动记录。

## ZIP 中的证据

| 文件 | 信息与用途 |
|---|---|
| `compatibility-feedback.json` | `schema_version=1`；会话、采集时间、App、系统构建/指纹/安全补丁、权限状态、当前阶段、兼容报告和关联文件名。便于程序归类与版本比较 |
| `compatibility.json` | 实读 chip / firmware / NXP_MW / source、识别备注、路由、状态、缺少接口；实际 INfcAdapter 方法签名清单及截断标记；可读到的 ROM 版本属性 |
| `vendor-info.json` | shell UID、小米服务是否存在、厂商方法签名、只读 getter 的值或异常。手动检查也采集；服务不可用则在事件中说明 |
| `environment.json` | 会话、机型、设备代号、Android SDK、系统指纹和 App 版本 |
| `events.jsonl` | 时间与单调时钟、选择通道、异常堆栈、NCI 请求/响应、Tag / ISO-DEP / D1 阶段和恢复事件；仅记录实际发生的操作 |
| `nfc-system.log` | 复现时采集的 NFC 服务及 HAL 相关日志，含采集失败、丢行/截断记录；需要已连接 shell |
| `q-poll-state.json` / `q-poll-cleanup.json` | 专用会话状态、错误、配置和恢复核验结果；只在进入对应路径时生成 |
| `nfc-before.txt` / `nfc-after.txt` | 会话前后 NFC 服务快照；需要已连接 shell |

`related_files` 是可能关联的文件列表，不保证每个文件都存在。只读检查通常没有 Tag、APDU、HAL 或恢复证据；缺少这些文件不能解释为操作成功。选过照片的推图会话还可能包含原有的预览、点阵和通信记录。

## 如何利用反馈

先按芯片与系统构建归组，对比接口的完整参数/返回类型、controller 来源与状态。接口缺失时评估是否有其它厂商入口；芯片未识别时补充只读识别，控制器未适配时研究对应协议。接口齐全但命令失败则结合原始 OID、响应、异常与 HAL 日志定位拒绝阶段。发现标签后再核对 ISO-DEP、D1 和屏幕返回状态。

日志可以缩小问题范围，不能凭方法清单推断未知厂商协议，也不能证明射频供电和实屏刷新。补充后端后仍需相应手机验证。
